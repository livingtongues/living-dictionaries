# Import workflow v2 — post-Enxet audit

First production import (`.issues/enxet-import.md`, 10 rounds) is done. This issue
folds everything it taught us back into the three surfaces the workflow lives on:

1. **The kickoff brief** — the message body generated by
   `POST …/files/request-import` (what Jacob copies into an agent session).
2. **The public API guides** — `site/src/lib/api/v1/guides/*` (the workflow itself;
   identical for outsiders and for us).
3. **A short knowledge page** — only the parts that pertain to *us* (insider access,
   and the closing hand-back to Jacob).

## Decisions (Jacob, 2026-07-25)

- ✅ **Source row + file link happen at the START of a job**, not after verification.
  `source_files.source_id` therefore stops being the "import finished" marker; the
  marker becomes **the import-request thread being resolved in /admin**.
- ✅ Manager-visible **"Import in progress" pill** once we've linked the file.
- ✅ The finishing agent **drafts the requester-facing summary** into the thread's
  `triage_draft_reply` so Jacob's last step is: read → use draft → send → resolve.
- ✅ `importing.md` stays ONE file: scannable runbook on top, tightened prose below.
  War stories stay **generic and brief** — every import differs.
